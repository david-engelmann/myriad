# myriad Contract

This Contract is the executable spec for myriad. Every obligation is checked by a named test or by a named check. The Contract is reported as met or not met in the README programme status.

## Setup obligations

- SETUP-1. The repo carries AGENTS.md with the canonical template verbatim
  above its marked line and the repo annex below it. Test,
  rust/tests/test_setup.rs.
- SETUP-2. The README programme status states the closed round count out
  of 100 and reports this Contract as met or not met. Test,
  rust/tests/test_setup.rs.
- SETUP-3. The codepoint scan at rust/src/bin/codepoint_scan.rs counts U+2014
  and U+2013 in every Markdown and text file in the repo and requires
  zero of each. The scan runs in the local gate and in CI.
- SETUP-4. Every fixture and example committed to this repo is synthetic
  and written for this repo. Nothing real is ever committed. Check, a
  manual sanitization review of every added fixture and example, with
  its result recorded in the gate report.

## First slice obligations, stub form

The full Contract for the first slice is the first build act of this repo. These stubs state the obligations the first slice will be held to, in the form they will be extended.

- MY-1. An exploration holds one question and a tree of branches, each branch holding its parent, its prompt, its state as open, taken, or abandoned, and, when abandoned, the reason it died. Test, the first slice tests.
- MY-2. The map renders the whole tree as text a reader can walk, with taken and abandoned paths both visible and abandoned paths carrying their reasons. The same exploration always renders byte identical output. Test, the first slice tests.
- MY-3. No two open branches in one exploration carry the same prompt, so branches cannot silently duplicate each other. Test, the first slice tests.
- MY-4. The first slice forks one question into tens of branches, not a thousand, and the count of branches is reported from the tree itself. Test, the first slice tests.

## First slice obligations, full form

This section extends the stub section above, which stays standing as the record of the form these obligations started in. The full form below is the text slice 2 is held to. Where the two disagree, the full form governs.

### The exploration shape

An exploration is one JSON object with the fields named here. The field question is a non empty string. The field branches is a list of branch objects, and the list may be empty. Each branch object holds an id field with a non empty string, a parent field holding null for a root or the id string of another branch, a prompt field with a non empty string, and a state field holding one of the three state words open, taken, and abandoned. A branch in state taken holds a finding field with a non empty string and holds no reason field. A branch in state abandoned holds a reason field with a non empty string and holds no finding field. A branch in state open holds neither a finding field nor a reason field. Fields the contract does not name are ignored, and the exploration the loader returns carries only the named fields. Test, rust/tests/test_explorations.rs.

### MY-1 full form, the loader names every malformed field and never raises

The loader entry points are load_exploration_text and load_exploration_file in the explorations module. Each returns a pair of the exploration and the list of defects it found. A clean input returns the exploration and an empty defect list. A malformed input returns no exploration and a defect list naming every malformed field the loader could reach, and neither entry point ever raises on malformed content. A file that cannot be read returns the single defect named file cannot be read. Text that is not JSON at all draws the defect named input is not valid JSON, and input nested too deeply for the JSON parser to read draws the same defect. JSON that parses to something other than an object draws the defect named input is not a JSON object. An absent top level field draws missing field and the field name. A top level field of the wrong kind draws field and the field name and has the wrong type. An empty question draws field question is empty. A branch that is not an object draws branch and its index and is not an object, and branch indexes count from zero. Inside a branch, an absent field draws branch and the index and is missing field and the field name. A field of the wrong kind draws branch and the index and field and the field name and has the wrong type. An empty string field draws branch and the index and field and the field name and is empty. A state string that is none of the three state words draws branch and the index and field state is not a known state. A finding or a reason carried by a branch in a state that forbids it draws branch and the index and field and the field name and is not allowed in state and the state word. A string holding an unpaired surrogate cannot be printed or written as UTF-8 text, and a text field holding one draws the holds an unpaired surrogate defect in the shape of its field. One malformed input can draw several defects in one pass, and the loader keeps naming fields after the first defect it finds. Test, rust/tests/test_explorations.rs.

The loader also names the structural defects of the tree. A branch whose id repeats the id of an earlier branch draws duplicate branch id and the id. A branch whose parent names no branch in the exploration draws branch and the branch id and parent and the parent id and does not exist. A branch whose parent chain loops without reaching a root draws branch and the branch id and has a cycle in its parent chain. The duplicate id check runs over every branch carrying a valid id. The parent checks run over every branch carrying a valid id and a valid parent value, and a parent is satisfied when any branch in the exploration carries that id. An exploration carrying any structural defect returns no exploration. Test, rust/tests/test_explorations.rs.

### MY-2 full form, the map renders the whole tree and never changes

The render_map function in the explorations module takes a loaded exploration and returns the map as a list of lines, and the map is a pure function of the exploration. The first line names the question, in the form question, and the question text. The walk that follows is depth first. Roots stand in the order they appear in the branches list, and the children of each branch stand in the order they appear in the branches list. Each branch line carries two spaces of indent per depth level, then the branch id, then the state word in parentheses, then the prompt. A taken branch carries one more line of its own, indented one level deeper than the branch line, in the form finding, and the finding text. An abandoned branch carries one more line of its own, indented one level deeper than the branch line, in the form reason, and the reason text. The last line counts the branches, in the form branches and the total and open and the open count and taken and the taken count and abandoned and the abandoned count. The count_by_state function in the same module returns the total and the three counts, counted by walking the branches of the exploration, and the summary line and the check command both read their numbers from it. The same exploration always renders the same lines, byte identical. Test, rust/tests/test_map.rs, and the golden map held in rust/tests/test_examples.rs.

### MY-3 full form, no two open branches carry the same prompt

No two branches in state open in one exploration carry the same prompt, and the loader enforces the rule at load time. A later open branch whose prompt repeats the prompt of an earlier open branch draws branch and the branch id and repeats the prompt of open branch and the earlier branch id. A prompt shared between an open branch and a branch in state taken or abandoned draws no defect, and two branches outside state open may share a prompt. Test, rust/tests/test_explorations.rs.

### MY-4 full form, recorded forking into tens of branches

Branch generation in this slice is recorded, not live. No live call is made anywhere in the slice, and no branch committed to this repo was produced by a model. The fork_skeleton function in the fork module takes a question and a list of branch prompts and builds the exploration skeleton a live forker would emit, one root branch per prompt, every branch in state open, with ids in the form b01, b02, and onward in prompt order. The skeleton loads clean under the MY-1 loader whenever its inputs are sound. The helper raises ValueError on an empty question, on a prompt that is not a string, on an empty prompt, and on two prompts that are the same, because no sound skeleton exists for those inputs. The slice forks one question into tens of branches, not a thousand, and the example exploration under examples carries tens of branches across all three states. The dibs claim the annex names stays a later obligation, and no branch in this slice carries one. Test, rust/tests/test_fork.rs and rust/tests/test_examples.rs.

### The command line surface

The cli module provides a main function and a console script named myriad with two commands. The map command takes one file holding an exploration and prints the map, or prints its defects and exits with status one when the exploration is malformed. The check command takes one file holding an exploration and prints the branch counts read from the tree, or prints its defects and exits with status one when the exploration is malformed. The counts print as four lines naming the total and then the count in each state. Every printed output is deterministic, so the same inputs always print the same bytes. Test, rust/tests/test_cli.rs.

## Round 1 repair amendments

This section records the repairs the Round 1 reviews required. Each amendment names the obligation it amends and the finding it closes, and every earlier text stays standing. Where an amendment and an earlier text disagree, the amendment governs.

### FIX-MY-3, amending MY-2

The map rendering walks the tree without recursion, so an exploration the loader accepts renders at any depth the loader accepts. The map command prints the map of a certified sound file and never dies on one. This amendment closes the red team Major finding that a loader valid chain raised RecursionError in the renderer once its depth passed the interpreter limit. Test, rust/tests/test_map.rs and rust/tests/test_cli.rs.

### FIX-MY-4, amending MY-1

The loader resolves each parent chain once for the whole exploration, sharing the outcome of every chain it has already walked. Load time grows with the size of the exploration and not with the square of its depth, and a deep cycle is named as fast as a shallow one. Every defect the loader named before this amendment keeps its wording, a chain leading into a cycle still draws the cycle defect, and a parent whose own fields are defective still counts as existing. This amendment closes the red team Minor finding that the parent chain walk was quadratic in tree depth. Test, rust/tests/test_explorations.rs.

### FIX-MY-5, amending MY-4

The fork helper refuses a question or a prompt holding an unpaired surrogate with the same ValueError it raises for its other unsound inputs. MY-1 names such a string as malformed, and the loads clean promise of MY-4 holds only when the helper refuses every input no sound skeleton exists for. This amendment closes the red team Minor finding and the spec fidelity condition on the fork boundary. Test, rust/tests/test_fork.rs.

## Round 2 obligations, full form

This section states the obligations the third slice is held to, in full form from the start. The stub section and the first slice sections stay standing above. Where this section and an earlier text disagree, this section governs.

### The exploration shape, Round 2 extension

A branch object may hold one more field beyond the fields the first slice shape names. The field claim holds a non empty string, the label of the fork that claimed the branch. The field is optional in every state, and a branch holding no claim field is the same branch the first slice shape describes. Fields the contract does not name are still ignored, and the exploration the loader returns carries the claim only on a branch whose input carried one. Test, rust/tests/test_claims.rs.

### MY-5 full form, the dibs claim on a branch

The claim a branch may carry is the dibs claim the repo annex names, and this obligation discharges the later obligation the annex and MY-4 full form recorded. The sentence in MY-4 full form that the dibs claim stays a later obligation speaks for the first slice and stays standing as its record. From this round the claim is part of the branch shape, and a branch in any slice may carry one.

The loader reads the claim field under the same reading it gives every other optional text field of a branch. A claim of the wrong kind draws branch and the index and field claim has the wrong type. An empty claim draws branch and the index and field claim is empty. A claim holding an unpaired surrogate draws branch and the index and field claim holds an unpaired surrogate. A claim that draws a defect makes the exploration malformed, as any field defect does, and the loader keeps naming fields after it. A claim is allowed in all three states and never interacts with the finding and reason rules of the state the branch stands in. Test, rust/tests/test_claims.rs.

Two branches may carry the same claim label, and one label may span branches in different states and in different parts of the tree. A claim names which fork owns the exploration work on a branch, and it says nothing about the worth of the branch. No rendering in this repo reads a claim as a judgement on the branch it stands on.

The map renders a claimed branch on its branch line, with the prompt followed by a comma and the words claimed by and the claim label. A branch carrying no claim renders exactly the branch line the first slice rendered, and the map of an exploration carrying no claims anywhere is byte identical to the map the first slice rendered. The counts line of the map is unchanged. Test, rust/tests/test_claims.rs and rust/tests/test_map.rs.

The render_claims function in the explorations module takes a loaded exploration and returns the claims listing as a list of lines, and the listing is a pure function of the exploration. The first line names the question, in the form question, and the question text. Then one line stands for each claim label the exploration carries, with the labels in alphabetical order of the label text, in the form claim and the label and branches and the count of branches carrying that label and open and the open count among them and taken and the taken count among them and abandoned and the abandoned count among them. Then, when at least one branch carries no claim, one last line stands in the form unclaimed and branches and the count of branches carrying no claim and open and the open count among them and taken and the taken count among them and abandoned and the abandoned count among them. The listing of an exploration with no branches is the question line alone. Test, rust/tests/test_claims.rs.

The fork helper builds skeletons whose branches carry no claim field, and a skeleton loads and lists as an exploration of unclaimed branches. Test, rust/tests/test_claims.rs.

### MY-6 full form, the territory census

The render_census function in the explorations module takes a loaded exploration and returns the territory census as a list of lines, and the census is a pure function of the exploration. The first line names the question, in the form question, and the question text.

The taken section stands next, and it stands only when the exploration holds at least one branch in state taken. The section opens with the line taken. Inside it, the taken branches stand grouped under the claim label each one carries, with the labels in alphabetical order of the label text, and each group opens with a line of two spaces and the word claim and the claim label. Each branch in a group stands on its own line of four spaces, in the form the branch id and finding and the finding text in full, and the branches inside a group stand in the order they appear in the branches list. Taken branches carrying no claim stand in one last group inside the section, and that group opens with a line of two spaces and the word unclaimed.

The abandoned section follows, in the same shape with the word reason in place of the word finding, and it stands only when the exploration holds at least one branch in state abandoned.

The open section stands last, and it stands only when the exploration holds at least one branch in state open. The section opens with the line open, and each open branch stands on its own line of two spaces, in the form the branch id and prompt and the prompt text, in the order the open branches appear in the branches list, with no grouping by claim.

The census closes with the counts line in the same form the map closes with. The census and the map read their counts from the same count_by_state function, so the two renderings of one exploration always agree on the counts they state. An exploration with no branches renders the question line and the counts line and no section. Test, rust/tests/test_census.rs.

### The command line surface, Round 2 extension

The cli module gains two commands beside map and check. The claims command takes one file holding an exploration and prints the claims listing, and the census command takes one file holding an exploration and prints the census. Each prints the defects of a malformed exploration and exits with status one, exactly as the map command does, and a sound file exits with status zero. Test, rust/tests/test_cli_round2.rs.

## Round 3 obligations, full form

This section states the obligations the fourth slice is held to, in full form from the start. The stub section and the first and second slice sections stay standing above. Where this section and an earlier text disagree, this section governs.

### The atlas shape

An atlas is one JSON object with the fields named here. The field title is a non empty string. The field entries is a list of entry objects, and the list may be empty. Each entry object holds a label field with a non empty string and an exploration field holding one exploration in the shape the first slice section states. Entries embed whole explorations rather than naming explorations held elsewhere, because every file this repo reads stands on its own and an atlas a reader cannot load whole from one file is an atlas a reader cannot check. Fields the contract does not name are ignored at the atlas level and at the entry level, and the atlas the loader returns carries only the named fields, with each exploration in the form the MY-1 loader returns. Test, rust/tests/test_atlas.rs.

### MY-7 full form, the atlas loader names every malformed field and never raises

The loader entry points are load_atlas_text and load_atlas_file in the atlas module. Each returns a pair of the atlas and the list of defects it found. A clean input returns the atlas and an empty defect list. A malformed input returns no atlas and a defect list naming every malformed field the loader could reach, and neither entry point ever raises on malformed content. A file that cannot be read returns the single defect named file cannot be read. Text that is not JSON at all draws the defect named input is not valid JSON, and input nested too deeply for the JSON parser to read draws the same defect. JSON that parses to something other than an object draws the defect named input is not a JSON object. An absent top level field draws missing field and the field name. A top level field of the wrong kind draws field and the field name and has the wrong type. An empty title draws field title is empty. A title holding an unpaired surrogate draws field title holds an unpaired surrogate, and a title holding a newline or a carriage return draws field title holds a newline or a carriage return. Test, rust/tests/test_atlas.rs.

An entry that is not an object draws entry and its index and is not an object, and entry indexes count from zero. Inside an entry, an absent label draws entry and the index and is missing field label. A label of the wrong kind draws entry and the index and field label has the wrong type. An empty label draws entry and the index and field label is empty. A label holding an unpaired surrogate draws entry and the index and field label holds an unpaired surrogate, and a label holding a newline or a carriage return draws entry and the index and field label holds a newline or a carriage return. These label defects name the entry by its index and never print the label value, because a label that drew a defect is a value no rendering may carry. Test, rust/tests/test_atlas.rs.

Each entry names its defects under a prefix that stands in the defect text in place of the entry itself. The prefix is entry and the label when the entry carries a label that drew no defect, and entry and the index when it does not. An absent exploration field draws the prefix and is missing field exploration. An exploration value that is not a JSON object draws the prefix and field exploration is not a JSON object. An exploration value that is a JSON object is validated by the MY-1 rules through the same validation the exploration loader runs, and every defect that validation draws stands in the atlas defect list as the prefix and the MY-1 defect wording unchanged, so a defect of an entry reads with the entry label standing in it and a reader knows which entry is malformed. A malformed entry never raises and is never silently dropped, and an atlas carrying any defect in any entry returns no atlas at all, so the atlas loads only whole. Test, rust/tests/test_atlas.rs.

Labels are unique across the atlas. The uniqueness check runs over every entry carrying a label that drew no defect, whatever else is malformed in the entry. A label carried by two entries draws duplicate entry label and the label and entries and the index of its first entry and and the index of the later entry, and a label carried by three entries draws that defect twice, once for each later entry against the first. The loader names the title and entries defects first, then the defects of each entry in entry order, then the repeated label defects in the order of the later entry. The loader keeps naming fields after the first defect it finds, as the exploration loader does. Test, rust/tests/test_atlas.rs.

### MY-8 full form, the atlas rendering

The render_atlas function in the atlas module takes a loaded atlas and returns the atlas rendering as a list of lines, and the rendering is a pure function of the atlas. The first line names the atlas, in the form atlas and the title. One section then stands for each entry, in the order the entries stand in the atlas. A section opens with the line entry and the label. The section then carries the lines of the map of the entry exploration exactly as render_map returns them, the question line, the tree lines, and the counts line, byte for byte the lines the map command prints for that exploration on its own. The section closes with the claim lines of the entry exploration exactly as render_claims returns them after its question line, one line for each claim label with its counts in the order the claims listing states, and the unclaimed line only when the entry holds a branch carrying no claim. Test, rust/tests/test_atlas.rs and rust/tests/test_examples_round3.rs.

The rendering closes with one atlas counts line, in the form atlas and entries and the count of entries and the counts line form the map closes with, read over the union of the branches of every entry in atlas order. The atlas counts are read from the same counting path the map, the claims listing, and the census read, run over that union, so the atlas counts always equal the sum of the section counts, and no second counting path exists for the atlas to disagree with itself. The rendering adds no word of its own beyond atlas, entry, and entries to the words the map and the claims listing already print. No section is ranked, ordered, or compared against another anywhere in the rendering, and no entry stands before another for any reason but its place in the atlas. An atlas holding no entries renders its title line and its counts line and no section. An atlas whose entries hold a deep or a wide exploration renders whole under the same iterative discipline the map holds, and an atlas whose entries sum past a thousand branches renders whole. Test, rust/tests/test_atlas.rs.

### The command line surface, Round 3 extension

The cli module gains one command beside map, check, claims, and census. A malformed atlas prints the line invalid atlas and then one line for each defect in the form defect and the defect text, exactly as the exploration commands print the defects of a malformed exploration, and a sound file exits with status zero. Test, rust/tests/test_cli_round3.rs.

## Round 4 obligations, full form

This section states the obligations the fifth slice is held to, in full form from the start. The stub section and the first, second, and third slice sections stay standing above. Where this section and an earlier text disagree, this section governs.

### MY-9 full form, the atlas index reading
